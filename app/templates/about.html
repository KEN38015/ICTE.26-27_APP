How the Smart School Assistant works

Who it's for

The assistant is built for SenTia's secondary and high school students. Primary school is not covered. The calendar is the secondary calendar for 2026–2027.

Architecture: UI → logic → data → response

  1. UI (Jinja2 templates + HTMX): you type or say “Where is the ICT room?”. HTMX sends it to the server without reloading the page.
  2. Logic (app/search.py): validates the input, applies privacy rules, detects the intent (here: location), corrects spelling, and scores every record by keyword and phrase matches.
  3. Data (data/*.csv, kept up to date from the team's Google Sheet): the best-matching record is found, e.g. room B4-07, the ICT Room on floor 4 of Zone B.
  4. Response: the server renders a result card with the room, building, floor, step-by-step directions and a map, and HTMX swaps it into the page.

If nothing matches well enough, the assistant says so instead of guessing. It never invents information.

Privacy

  • All student data is fictional. No addresses, phone numbers, grades or medical information are stored.
  • Student profiles are checked on the server: students see only their own profile, teachers see students they teach, admins see all.
  • Passwords are stored as salted PBKDF2 hashes. The search log never stores usernames.

AI usage declaration

AI (Claude, by Anthropic) was used as a coding assistant to plan the architecture, write and test code, turn the school's documents and photos into data files, and create the fictional student data. The team chose the requirements, design and technology, reviewed the code, and is responsible for the final data and testing. The assistant itself does not call any live AI service: every answer comes from the school's approved data using programmed rules. See docs/AI_USAGE.md in the repository for details and prompt history.
